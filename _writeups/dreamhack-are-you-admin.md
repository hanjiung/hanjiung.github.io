## 코드에서 찾은 단서

사용자 소개 화면을 만드는 템플릿에서 두 입력값의 출력 방식을 비교했습니다. 둘 다 사용자가 입력한 문자열인데, 템플릿은 한쪽의 HTML 특수문자를 이스케이프하고 다른 쪽은 HTML로 해석할 수 있게 출력했습니다.

이 차이에서 풀이의 가설을 세웠습니다. 사용자가 쓴 소개 문구를 브라우저가 페이지의 일부로 해석한다면, 작성자가 다른 사람의 화면 구성에도 영향을 줄 수 있습니다. 같은 화면에 표시되는 값이라도 출력되는 자리마다 처리 방식을 확인해야 했습니다.

## 배운 개념

풀이를 정리하며 **주소로 값을 전달하는 단계**와 **그 값을 화면에 표시하는 단계**를 구분했습니다. 예를 들어 `R&D`라는 문구에서 같은 `&`도 쓰이는 위치에 따라 표현이 달라집니다.

| 위치 | 표현 예시 | 이유 |
| --- | --- | --- |
| URL의 쿼리 값 | `R%26D` | `&`를 다음 매개변수의 구분자로 읽지 않고 값의 일부로 전달합니다. |
| HTML 본문의 텍스트 | `R&amp;D` | 브라우저가 화면에 원래 문구인 `R&D`를 표시합니다. |

주소에서 원래 문자열을 복원한 뒤에는 HTML에 맞는 출력 처리가 다시 필요합니다. URL 인코딩을 거쳤다는 사실만으로 화면에서 어떻게 해석될지 알 수는 없습니다.
