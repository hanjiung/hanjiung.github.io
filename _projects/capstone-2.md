### 모델·파서·웹의 연동 기준 정하기
{: #팀원들이-같은-입력으로-개발할-수-있게-한-일 }

팀장·PM으로서 가장 먼저 정한 것은 세 모듈이 주고받을 데이터였습니다. 요청·응답 형식을 JSON Schema로 정의하고 정상·오류 예시를 만들어, 팀원들이 모의 응답으로 각자 개발을 시작할 수 있게 했습니다. 담당자별 일정과 연동을 막는 이슈를 추적하고, 실제 모듈을 하나씩 연결할 때마다 같은 회귀 테스트와 팀 QA 결과로 릴리스를 점검했습니다.

### 질문과 첨부 문서에 같은 토큰 쓰기
{: #탐지-결과를-원문의-정확한-위치에-적용한-방법 }

정규식과 한국어 문맥 모델이 찾은 구간을 원문과 대조하는 코드를 작성했습니다. 이모지 뒤에 이메일이 나와도 Python 탐지기와 Node.js 프록시가 같은 글자를 가리키도록 위치 단위를 **유니코드 코드 포인트**로 맞췄습니다. 두 탐지 결과가 겹치면 긴 구간을, 길이까지 같으면 정규식 결과를 선택했습니다.

질문과 첨부 문서에 같은 이메일이 있으면 두 곳 모두 `[EMAIL_001]`로 바꿉니다. 유형과 원문을 토큰에 연결하는 대응표를 요청별로 만들어 프록시 메모리에 두고, 사용자에게 답변을 돌려줄 때 참조하도록 했습니다.

### 응답이 토큰 중간에서 끊길 때
{: #masking-example }

서버 전송 이벤트(SSE)로 도착하는 답변은 토큰 한가운데서 끊길 수 있습니다. 일반 문장은 즉시 보내고, 등록된 토큰의 시작 부분과 일치하는 문자열만 다음 조각까지 보관하도록 구현했습니다.

| 도착한 응답 조각 | 사용자가 읽는 내용 |
| --- | --- |
| `담당자는 [PER` | ‘담당자는 ’을 먼저 표시하고 `[PER`는 보관합니다. |
| `SON_001]입니다.` | 완성된 `[PERSON_001]`을 찾아 ‘김민수입니다.’를 이어 보냅니다. |

## 웹 동작 과정
{: #web-demo }

팀이 개발한 웹에 가상 고객 방문 문서 `CUSTOMER_D_005.txt`를 첨부하고 **“분석해줘”**라고 요청했습니다. 데모 응답(Mock) 모드에서 연락처 하나가 돌아오는 과정입니다.

1. **처리 상세.** 질문은 두 칸 모두 ‘분석해줘’입니다. 첨부 문서에서는 `010-0000-0041`이 `[PHONE_001]`로, `customer041@example.com`이 `[EMAIL_001]`로 바뀝니다.
2. **치환 내역.** 이 요청의 치환은 **21건**입니다. 첫 전화번호와 이메일의 탐지 출처는 모두 `REGEX`이며 각 문자 범위는 `209–222`, `249–272`입니다.
3. **복원 응답.** 사용자가 읽는 방문 안내에는 다시 `010-0000-0041`과 `customer041@example.com`이 표시됩니다.

## 검증 결과
{: #evaluation }

**프록시 회귀 테스트 25개가 모두 통과했습니다.** 입출력 규격을 검사하는 10개와 프록시 동작을 검사하는 15개로, 질문·문서 간 토큰 재사용과 스트리밍 복원을 확인했습니다.

팀은 졸업논문에서 가상 회의록 TXT로도 왕복 처리를 검증했습니다. 문맥 모델이 두 사람의 이름을, 정규식이 각자의 이메일과 전화번호를 찾았습니다. 최종 답변에는 여섯 값이 모두 복원됐고 회의 일정과 후속 작업 기한도 남았습니다. PDF와 DOCX에서는 여러 페이지와 표의 텍스트 추출 순서를 확인했습니다.

## 느낀 점
{: #lessons }

‘문자 위치를 보낸다’는 합의만으로는 부족했습니다. 이모지 하나를 두 서버가 다르게 세면 탐지기가 이메일을 맞혀도 프록시는 다른 글자를 가릴 수 있습니다. PM으로서 팀원들과 가장 먼저 공유하고 싶은 것도 이렇게 **입력 한 줄과 마지막에 보여야 할 답변 한 줄**입니다. 두 줄이 있어야 서로 다른 모듈을 같은 기준으로 점검할 수 있었습니다.

## 개선할 점
{: #next-steps }

- **외부 전송 직전의 검증.** 테스트용 수신 서버에서 실제로 받은 질문과 첨부 내용을 대조해 가상 연락처 원문이 남는지 확인하고 싶습니다. PDF·DOCX도 추출 이후의 마스킹과 복원까지 범위를 넓힐 수 있습니다.
- **예외와 동시 요청.** 모델이 토큰 철자를 바꾸거나 응답이 끊겼을 때 보이는 답변을 확인하고, 두 요청에 각각 `[EMAIL_001]`이 생겨도 각 사용자가 자기 주소만 받는지 검사하고 싶습니다.
- **사용자가 기다리는 시간.** 업로드부터 첫 번째 복원 문장이 표시될 때까지 구간별로 측정해 문서 추출, 탐지, 답변 생성 중 어디를 먼저 개선할지 판단할 수 있습니다.
