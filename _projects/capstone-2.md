**2026 캡스톤 프로젝트 · 팀장·PM**

사용자가 메일 초안에 첨부 문서의 회신 주소를 넣어 달라고 하면, 외부 언어 모델(LLM)은 `[EMAIL_001]`을 넣은 초안을 작성할 수 있습니다. 이 프록시는 질문과 문서에 나온 같은 주소를 하나의 토큰으로 바꿔 모델에 보내고, 사용자에게 답변을 보여줄 때 원래 주소로 되돌립니다. 저는 팀의 개발 일정을 관리하고 이 마스킹·복원 과정을 구현했습니다.

## 팀장·PM으로 정한 통합 순서

모델, 문서 파서, 웹을 담당한 팀원들이 병렬로 개발할 수 있도록 요청·응답 형식을 먼저 맞췄습니다. 필수 항목과 개인정보의 위치 표기 방식을 JSON Schema와 정상·오류 예시로 정리했습니다. 팀원들은 이 기준에 맞춘 모의 응답(Mock)으로 각자 맡은 기능을 연결할 수 있었습니다.

작업마다 담당자와 마감일을 정하고, 일일 점검에서 다음 단계의 진행을 막는 이슈를 추적했습니다. 실제 모듈이 준비되면 하나씩 교체하면서 같은 회귀 테스트를 돌렸습니다. 릴리스 검수에는 팀의 QA 결과를 모았고, 평가 계획에는 개인정보 유형별 오탐·미탐과 첫 응답까지 걸리는 시간을 포함했습니다.

## 질문과 문서에서 같은 값을 가리는 방법

이메일·전화번호처럼 형식이 있는 값은 정규식으로 찾고, 모델이 찾아낸 구간과 겹치면 병합했습니다. 이모지 다음에 개인정보가 와도 Python 탐지 서버와 Node.js 프록시가 같은 글자를 가리키도록 위치 단위를 유니코드 코드 포인트로 통일했습니다.

한 요청 안에서는 질문과 첨부 문서가 하나의 대응표를 공유하게 했습니다. 같은 유형의 같은 값에는 같은 토큰을 부여하고, 원문과 토큰의 대응표는 프록시에서 복원에 사용했습니다.

## 응답이 토큰 중간에서 끊길 때
{: #masking-example }

모델의 답변은 서버 전송 이벤트(SSE)를 통해 조각 단위로 도착합니다. 첫 조각에 `[EMAIL_`이 오고 다음 조각에 `001]`이 오면, 두 조각을 이어야 주소를 복원할 수 있습니다. 저는 앞의 일반 문장은 바로 표시하고, 토큰일 수 있는 끝부분만 보관했다가 다음 조각과 이어서 복원하도록 구현했습니다.

아래는 가상의 이메일 주소와 두 조각으로 나눈 모의 응답으로 확인한 예시입니다.

| 구간 | 텍스트 |
| --- | --- |
| 사용자가 보낸 질문 | `회신 주소(review@example.org)를 알려 줘.` |
| 외부 모델에 전달하는 질문 | `회신 주소([EMAIL_001])를 알려 줘.` |
| 모델 응답의 첫 조각과 다음 조각 | `회신 주소는 [EMAIL_` + `001]입니다.` |
| 사용자가 읽는 답변 | `회신 주소는 review@example.org입니다.` |

## 검증 결과

합성 입력으로 관련 자동 테스트를 다시 실행한 결과 **25개 모두 통과**했습니다. 입출력 계약 테스트 10개는 필수 항목과 개인정보 위치가 규격에 맞는지 확인했습니다. 프록시 테스트 15개는 정규식 탐지, 질문·문서 간 토큰 재사용, 스트리밍 복원, 모의 모델을 연결한 요청·응답 흐름을 검증했습니다.
